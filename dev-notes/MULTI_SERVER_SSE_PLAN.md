# 다중 서버 Pub/Sub·SSE 기능 확인

## 목적과 범위
같은 애플리케이션 두 인스턴스에서 한 번의 투표 집계가 Redis Pub/Sub을 통해 양쪽 서버의 로컬 SSE 연결에 전달되는지 확인한다. 사용자가 CLI와 진행하도록 요청한 현재 작업이다. 부하 테스트나 장애 복구 기능은 이번에 구현·실행하지 않는다.

## 환경
- 동일 최신 빌드의 독립 JVM 두 개: A=127.0.0.1:8080, B=127.0.0.1:8081. 포트 충돌 시 빈 포트를 골라 결과에 명시한다. 현재 포트/PID를 먼저 확인하고 사용자 앱을 임의 종료하지 않는다.
- 같은 작업 디렉터리/.env/local 프로필로 같은 PostgreSQL·Kafka·Redis에 연결한다. 기존 인프라를 재사용한다. 비밀값을 출력하거나 기록하지 않는다.
- Kafka topic=vote-created, groupId=vote-log-group 유지. 파티션 수를 실제 확인한다. 현재 한 파티션이면 안정된 그룹에서 한 인스턴스만 할당받고 다른 인스턴스는 대기한다. 그룹 ID를 서버마다 다르게 바꾸지 않는다.
- 두 서버 모두 live-lunch-choice:ranking-changed를 구독한다. 로그는 서버별 파일/포트/PID로 구분하여 어느 서버가 집계하고 어느 서버가 알림을 받았는지 확인한다.
- 기존 VoteService 및 VoteResultResponse 통합 상태를 유지한다. 과거 별도 서비스·DTO 구현 안내로 되돌리지 않는다.

## 절차
1. git 상태/최신 코드/빌드를 확인하고 두 서버를 실행한다. 기존 앱은 적합하면 재사용한다. 서버 시작 시점의 DDL 동시 실행을 피하도록 순차 시작한다.
2. 양쪽 HTTP 응답, Redis 구독 준비 및 Kafka 그룹 할당 안정화를 확인한다. 준비 확인 전 발행하지 않는다.
3. 기준 후보 ID, DB 득표 수, Redis 점수, 그룹 offset/lag를 기록한다. 기존 DB와 Redis 전체 데이터가 같다고 가정하지 않고 변화량을 비교한다.
4. A와 B의 /api/votes/rankings/stream에 각각 연결하고 초기 ranking 이벤트를 받는다. 두 연결이 서로 다른 서버 포트임을 기록한다. curl -N은 60초 종료 후 자동 재접속하지 않으므로 필요 시 다시 연결한다.
5. A에 새 userId로 투표 한 건을 요청한다. HTTP201, voteId/eventId, Kafka 소비 서버, 점수 +1, Pub/Sub 양쪽 수신, 양쪽 SSE 최신 목록을 확인한다. 수신 순서가 아니라 같은 eventId와 결과로 연계한다.
6. 첫 요청의 처리가 끝난 뒤 B에도 다른 새 userId로 투표 한 건을 요청해 같은 확인을 반복한다. 총 두 투표의 기대 변화량은 +2다. HTTP 요청을 받은 서버와 Kafka 집계 서버는 달라도 정상이다.
7. 이벤트별 집계 로그가 한 서버에서 발생하고 알림 수신은 양쪽에서 발생했는지 확인한다. 최종 lag 해소와 DB/Redis 변화량, 각 SSE 최종 스냅샷을 기록한다.
8. 시작한 관측 연결을 정리하고 CLI가 직접 시작한 임시 앱만 정상 종료한다. 기존 사용자 앱/인프라는 유지한다. 최종 PID/포트 상태를 기록한다. 새 확인용 투표는 삭제하지 않고 ID를 기록한다.

## 성공 기준
- 독립된 서버 두 개에 각각 연결된 SSE 클라이언트가 동일한 최신 랭킹을 수신.
- 각 새 이벤트에서 Redis 점수는 정확히 +1, 양쪽 서버 Pub/Sub 수신 및 로컬 SSE 전송 확인.
- A/B 어느 서버로 요청해도 위 흐름 성립. 같은 서버의 SSE 두 연결만으로 대체하지 않는다.
- 실제 실행 결과와 예상 결과를 구분한다. 실패 시 해당 지점과 근거를 기록하고 현재 범위의 문제만 해결한다.

## 보존 및 기록
사용자 DB/Redis 초기화, FLUSHALL, 기존 토픽 삭제, offset reset, 임의 데이터 삭제를 하지 않는다. 필요한 테스트 투표 두 건만 추가한다. dev-notes/MULTI_SERVER_SSE_RESULT.md에 환경·명령·서버별 로그·eventId·전후 점수·SSE payload·미검증 항목을 기록하고 PROGRESS.md 상단과 이력을 갱신한다. 명령은 복사 가능한 한 줄로 제공한다. 데스크톱은 이번 턴에서 문서만 작성했으며 실험은 미실행이다.
